# BlackBox — evidence-led judge demonstration

28 September 2026. This supersedes `PITCH.md`. Consult [requirements](SIH26117_REQUIREMENTS.md), [Round 2 preparation](ROUND2_SUBMISSION_BRIEF.md) and `data/LIVE_WORKFLOW_REPORT.md` before presenting.

**Informed inference:** the strongest story is a confidential task carried from source to a correct, inspectable file, with a visible mistake caught along the way. The build is not yet proven ready for the complete demonstration.

## Opening

“Industrial staff need usable work products from confidential records. BlackBox keeps the workflow local: it reads authorized sources, plans work, selects local models, uses tools and produces inspectable files. We will show what the system did, what the checks established and where human approval remains necessary.”

## Sequence — proposed, not measured timing

1. **Boundary:** identify host, model hashes, runtime and isolation profile. Show native parent/child outbound probes and network monitoring during inference. Explain coverage; a badge is not certification.
2. **Scan to note:** start from a synthetic or authorized unseen inspection scan and controlled rule. Open the page, extract values, run calculations and produce DOCX. Check readings, results, citations and missing approval. Never use a truth sidecar as vision output.
3. **Different automatic model route and code:** display the actual selected model and reason. Execute generated code in isolation. Show independent numerical and negative-input assertions. Writing a script alone is not execution.
4. **Spreadsheet and caught error:** open XLSX, inspect input types, recalculate in a real engine and examine the decision/evidence. Introduce a broken reference in a separate copy and demonstrate rejection. Static validation is not numerical proof.
5. **Evidence:** open the run record and sources; show pending issues and approval state. Report cold/warm timing and peak memory only for the demonstrated configuration.

## Claim discipline

**Established fact:** software tests prove behavior only under their conditions. Mock results do not establish real-model quality. Synthetic P&ID sidecars do not establish image interpretation. A self-signed certificate is not an independent audit. Model-review acceptance is not proof of correctness.

Do not claim a three-minute workflow, universal zero egress, production security, independent expert accuracy, 10-million-document capacity, measured GPU speed or commercial-tool superiority without matching evidence. Preserve failed artifacts.

## If a run fails

Say: “This run did not meet its acceptance checks. Here is the failure and evidence.” Identify date/configuration if showing a previous recording. If no successful equivalent exists, show the tested component and label the complete workflow unfinished.
